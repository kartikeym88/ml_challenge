# Business Entity Resolution Challenge

Welcome to the team repository for the Business Entity Resolution Challenge! This repository serves as our central hub for code, data preprocessing, model training, and submission generation.

## 📁 Repository Structure

Our repository follows the exact structure required for the final challenge submission to ensure we are always ready to package our work.

```text
.
├── dataset/                    # ⚠️ IGNORED IN GIT: Place the downloaded .tsv files here (train/ and test/ folders)
├── output/                     # ⚠️ IGNORED IN GIT: Generated TSV files (matching_results.tsv, candidate_pairs.tsv)

│   └── business_entity_resolution/
│       ├── src/                # Our core Python scripts and modules
│       ├── requirements.txt    # Shared Python dependencies
│       └── README.md           # Instructions specifically for running the code end-to-end

├── .gitignore                  # Keeps large data and temp files out of our repo
└── README.md                   # This file (Team onboarding & workflow)
```

## 🚀 Getting Started (Setup Instructions)

**1. Clone the repository:**
```bash
git clone <YOUR_GITHUB_REPO_URL>
cd "ml challenge"
```

**2. Download the Dataset:**
*   Download the dataset from the challenge portal.
*   Extract the contents so that you have `dataset/train/` and `dataset/test/` folders at the root of the project. *(Note: These files are ignored by git to avoid bloating the repo).*

**3. Set up the Virtual Environment:**
```bash
python -m venv .venv
# On Windows:
.venv\Scripts\activate
# On Mac/Linux:
source .venv/bin/activate

# Install dependencies (once we add them to requirements.txt)
pip install -r code/business_entity_resolution/requirements.txt
```

## 👥 Team Work Division

To maximize efficiency and avoid merge conflicts, our workflow is divided into three focused areas.

### Member 1: Data Engineering & Blocking (Focus: Recall)
*   **Goal:** Build a robust candidate generation pipeline that dramatically reduces the search space without missing true matches.
*   **Tasks:**
    *   Implement data loaders for the `dataset/` `.tsv` files.
    *   Create normalization functions for names and addresses.
    *   Build the Blocking step (e.g., TF-IDF, MinHash/LSH).
    *   Write the pipeline step that outputs the initial `output/candidate_pairs.tsv`.
*   **Primary Working Area:** `code/business_entity_resolution/src/blocking.py` and `data_loader.py`.

### Member 2: NLP & Feature Engineering (Focus: Signal)
*   **Goal:** Generate highly informative features for every candidate pair generated by Member 1.
*   **Tasks:**
    *   Compute string distances (Jaro-Winkler, Levenshtein, Jaccard).
    *   Implement phonetic matching (Soundex, Metaphone).
    *   Generate lightweight embedding similarities (<8B params model like `all-MiniLM-L6-v2`).
*   **Primary Working Area:** `code/business_entity_resolution/src/features.py`.

### Member 3: ML Lead & Strategist (Focus: Precision / $F_{0.5}$)
*   **Goal:** Train the classifier, tune the threshold to maximize $F_{0.5}$, and ensure compliance with the submission rules.
*   **Tasks:**
    *   Create the local validation split mimicking the test set.
    *   Train a Gradient Boosting model (XGBoost/LightGBM) using Member 2's features.
    *   Perform rigorous probability threshold tuning.
    *   Generate the final `output/matching_results.tsv`.
    *   Validate the submission using `utils/validate_submission.py`.
    *   Fill out `Documentation_template.md`.
*   **Primary Working Area:** `code/business_entity_resolution/src/model.py` and `evaluate.py`.

## 🔀 Git Workflow (Important for Teamwork!)

Since we are 3 people working in parallel, please follow this workflow to avoid breaking each other's code:

1.  **Never push directly to `main`.**
2.  **Create a branch for your feature:**
    ```bash
    git checkout -b feature/your-name-or-task
    # example: git checkout -b feature/tfidf-blocking
    ```
3.  **Commit frequently with clear messages:**
    ```bash
    git add .
    git commit -m "Added jaro-winkler similarity function"
    ```
4.  **Push your branch and open a Pull Request (PR):**
    ```bash
    git push origin feature/your-name-or-task
    ```
5.  **Review & Merge:** Have at least one other team member quickly review your PR before merging it into `main`. Before creating a PR, always pull the latest `main` branch to ensure your code is compatible!

```bash
# To get the latest changes from everyone else:
git checkout main
git pull origin main
```

Happy coding! Let's win this! 🏆
